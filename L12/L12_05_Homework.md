# L12 · Домашнее задание: свой локальный MCP-сервер

**Что делаем:** с помощью ИИ создаём программу, которая читает условия занятия из файла на вашем компьютере. Вызываем её через настоящий MCP и проверяем ответ.

**Что получится:** проверочная программа → MCP → ваш server.py → sessions.json.

**Нужно:** Python 3.11+, ИИ-помощник из L11 и интернет для первой установки библиотеки. Ориентир: 60–90 минут. Код помогает написать ИИ; ваша работа — запустить, проверить и объяснить результат.

## 1. Подготовьте папку

Возьмите **L12_Local_MCP_Homework.zip** из материалов урока, распакуйте его и откройте папку **homework_local**. Работайте с распакованной папкой, а не внутри ZIP.

В ней уже есть:

- **sessions.json** — вымышленные условия одного занятия W101;
- **AI_PROMPT_RU.txt** — готовое задание для ИИ;
- **check.py** — программа, которая действительно вызывает сервер через MCP;
- **Run Check.cmd** — запуск проверки на Windows;
- **reference/server.py** — рабочий пример для разбора, если застряли.

Рядом с данными пока **нет вашего server.py**. Именно его нужно создать. Проверочная программа уже готова — переписывать её не нужно.

Откройте sessions.json текстовым редактором. JSON — текстовый формат данных: имена полей слева, значения справа. Это обычный файл на вашем компьютере.

~~~json
{
  "sessions": [
    {
      "id": "W101",
      "title": "MCP practice",
      "date": "2026-11-04",
      "start": "18:30",
      "timezone": "Europe/Warsaw",
      "duration_minutes": 90,
      "registration_required": true
    }
  ]
}
~~~

W101 — номер занятия, start — начало, duration_minutes — длительность, true у регистрации означает «нужна». Записи W999 в файле нет.

## 2. Попросите ИИ создать сервер

Откройте эту папку в ИИ-помощнике, которым пользовались в L11. Скопируйте **весь AI_PROMPT_RU.txt** и отправьте ему. Там уже указаны библиотека, функция, формат ответа и способ запуска.

Коротко задача звучит так:

> Создай рядом с sessions.json файл server.py — локальный MCP-сервер на Python. У него один инструмент get_session(session_id). Он каждый раз читает sessions.json и возвращает найденную запись. Для неизвестного ID возвращает found=false. Доступ только для чтения. Запуск через stdio. Проверку check.py не меняй.

Если ИИ работает только в чате, приложите sessions.json и requirements.txt вместе с промптом. Сохраните выданный код как **server.py**, без добавления .txt, рядом с данными.

На этом шаге ИИ помогает **написать программу**. Внутри сервера модель для чтения файла не нужна.

## 3. Запустите и увидьте первый ответ

На Windows дважды нажмите **Run Check.cmd**. Если Python ещё не установлен, установите Python 3.11+ с [официального сайта](https://www.python.org/downloads/) и повторите запуск. При первом запуске сценарий создаст .venv — отдельную среду Python — и установит библиотеку MCP из requirements.txt.

В текстовом окне программа check.py запустит ваш server.py как отдельный процесс. Связь идёт по MCP через **stdio**, то есть стандартный ввод и вывод процесса. Проверка запросит список инструментов и вызовет get_session для W101 и W999.

Должны появиться строки:

~~~text
[OK] tools/list: get_session
[OK] W101: found=true, start=18:30
[OK] W999: found=false
ГОТОВО: локальный сервер ответил через MCP.
~~~

Между ними будет полный ответ W101. В папке **results** появится JSON-отчёт с реальными запросами, ответами и снимком исходного файла. Сохраните этот первый отчёт.

Проверочная программа сама запускает локальный сервер. Адрес сайта и браузер для этого варианта не нужны. После проверки соединение закрывается, сервер завершается. Повторный запуск создаёт новый отчёт.

На macOS/Linux откройте терминал в этой папке:

~~~bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python check.py --lang ru
~~~

## 4. Докажите, что ответ берётся из файла

В sessions.json поменяйте **только** "start": "18:30" на "start": "20:00". Сохраните файл. ИИ может помочь с этим изменением; код сервера на этом шаге менять не нужно.

Снова запустите **Run Check.cmd**. Теперь должно быть:

~~~text
[OK] W101: found=true, start=20:00
[OK] W999: found=false
~~~

Сохраните второй отчёт. Возврат 20:00 после изменения файла показывает работающую связь с источником. Оставьте 20:00 в окончательном файле: преподаватель сможет повторить ваш последний запуск.

| Ваша проверка | Что должны увидеть |
|---|---|
| Запрос W101 до изменения | Запись найдена, начало 18:30 |
| Запрос W999 | found=false, выдуманных условий нет |
| Изменение файла и повторный вызов | Начало 20:00 без изменения кода сервера |

Если есть ERROR или нет [OK], скопируйте **точный текст ошибки** ИИ: «Помоги исправить запуск. Проверку check.py не меняй; объясни, что сломалось». После исправления запустите заново. Фраза «должно работать» не заменяет успешный вызов.

## 5. Что сдать

В **genai-homeworks/L12/** положите:

1. Ваш **server.py** и окончательный **sessions.json** со временем 20:00.
2. **Два JSON-отчёта** из results: до изменения и после. Каждый содержит оба вызова W101/W999.
3. **README.md** из 5–8 предложений по примеру ниже. Скриншот окна можно добавить.

Папку .venv сдавать не нужно. Если воспользовались reference/server.py, укажите это и всё равно выполните оба запуска самостоятельно.

Пример README — заполните по своему запуску:

> Я с помощью [название ИИ] создал локальный MCP-сервер для sessions.json. Клиент — готовая проверка check.py; сервер — мой server.py. Для W101 сначала получил начало 18:30. Для W999 сервер вернул found=false. Затем изменил время в файле на 20:00, повторил вызов и получил 20:00. Сервер читает только один файл. В проверке функцию выбирает код клиента; модель помогала написать сервер, но при вызове не использовалась.
